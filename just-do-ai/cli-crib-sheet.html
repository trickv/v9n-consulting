The Command Line for People Who've Never Used It

You'll spend most of this bootcamp in a terminal. If you've never opened one before, this page gets you oriented — what these words mean, how to move around, and how to find your files afterwards in Finder or Windows Explorer.

Which Terminal Am I Using?

On Mac it's easy. On Windows it's a mess — there are several things that all look like "a terminal" and they behave differently.
macOS

Open: Press ⌘ + Space, type "Terminal", hit Enter. Or find it in Applications → Utilities → Terminal.

What you get: A zsh shell. Your home folder is /Users/yourname. Everything "just works" the same as a Linux bootcamp example.

Windows — WSL / Ubuntu (recommended)

Open: Open the "Ubuntu" app from your Start menu. Or open Windows Terminal and pick "Ubuntu" from the dropdown.

What you get: A real Linux environment running inside Windows. Prompt looks like yourname@MACHINE:~$. Your home is /home/yourname, separate from your Windows files.

Why this one: Claude Code and most dev tooling assume a Linux/Mac environment. WSL gives you that without dual-booting. Every bootcamp example will work as-written here.

Haven't installed WSL yet? See the Pre-Class Setup Guide — it walks you through it.
Windows — PowerShell

Open: Start menu → type "PowerShell" or "Windows Terminal" → Enter. Prompt looks like PS C:\Users\yourname>.

What you get: Microsoft's modern shell. Fine for basic navigation. Most bootcamp examples written for bash/zsh will not work as-is — the syntax diverges once you get past cd/ls/mkdir.

Windows — Command Prompt (cmd.exe)

Open: Start menu → "Command Prompt". Prompt looks like C:\Users\yourname>.

What you get: The ancient Windows shell from the 1980s. Avoid it. Doesn't have pwd, ls is dir, scripting is painful. If you opened this by accident, close it and open WSL or PowerShell instead.

Windows — Git Bash / MinGW64

Where it comes from: Installed alongside "Git for Windows." Title bar often says MINGW64. Prompt shows your user, machine, and a path with forward slashes.

What you get: A bash shell bolted onto Windows using MSYS2/MinGW. Bash commands mostly work. It's a reasonable fallback if you can't install WSL, but WSL is still the better choice for this bootcamp — more things work, and it matches what your instructor is using.

The naming confusion: "Windows Terminal" is the window (the tabbed app). What runs inside it can be PowerShell, Ubuntu (WSL), Command Prompt, or Git Bash. If someone asks "which terminal are you in?" they mean which of those is running — check the prompt and the tab title.

The Four Commands You Actually Need

Learn these four and you can follow along with any bootcamp exercise. They work — with caveats — across every shell listed above.
pwd "print working directory"

Shows you where you are right now. When in doubt, run this.

$ pwd
/Users/patrick
ls "list"

Lists the files and folders in the current directory.

$ ls
Documents  Downloads  Desktop  Music  Pictures

Add -la to see hidden files and details: ls -la. (Flags like -la only work in bash/zsh/WSL — not in PowerShell's ls alias.)

cd "change directory"

Moves you into a folder. This is how you navigate.

$ cd Documents        # go into Documents
$ cd ..               # go UP one level
$ cd ~                # go to your home folder
$ cd                  # (same thing — home folder)
$ cd /tmp             # jump to an absolute path
Tab completion: Start typing a folder name and hit Tab. The shell finishes it for you. This is the single biggest time-saver in the CLI — use it obsessively.
mkdir "make directory"

Creates a new folder in your current directory.

$ mkdir my-first-project
$ cd my-first-project
$ pwd
/Users/patrick/my-first-project

Gotcha — spaces in folder names: cd My Project won't work. Use cd "My Project" (all shells) or cd My\ Project (bash/zsh only). Easier: don't use spaces in folders you'll touch from the CLI. Use my-project or my_project.

"Where Did My Folder Go?" — Finding CLI Stuff in the GUI

You made a folder in the terminal. Now you want to open it in Finder / Explorer. Here's how.

macOS — Finder

From the terminal, you can open the current folder in Finder directly:

$ open .              # opens current folder in Finder
$ open ~/Documents    # opens Documents in Finder

Or from Finder's menu: Go → Go to Folder… (⌘ + Shift + G), then paste a path like /Users/yourname/my-first-project.

To see hidden files in Finder (anything starting with ., like .claude): press ⌘ + Shift + . (period).

Windows + WSL — Explorer

From your WSL terminal, open the current folder in Windows Explorer:

$ explorer.exe .      # opens current folder in Explorer

WSL files live on a virtual Linux drive. To browse them from Explorer, type this in the Explorer address bar:

\\wsl$\Ubuntu\home\yourname

Or simpler: in the left-hand sidebar of Explorer, scroll down — there's a Linux entry with a penguin icon. Your WSL home is in there.

Performance tip: Keep your coding projects inside WSL (/home/yourname/…), not on the Windows side (/mnt/c/…). Files stored on the WSL side are dramatically faster for Git and build tools.

Windows native — Explorer

From PowerShell, open the current folder in Explorer:

PS> start .             # opens current folder in Explorer
PS> explorer .

Or in Explorer, click the address bar and type a path like C:\Users\yourname\my-first-project.

Going the Other Way — GUI to CLI

You have a folder open in Finder/Explorer and you want to cd into it.

macOS

  • Drag the folder from Finder onto the Terminal window — the full path gets pasted for you. Type cd first, then drag.
  • Or right-click the folder in Finder → hold Option → "Copy as Pathname."

Windows

  • In Explorer, click the address bar — it shows the real path. Copy it.
  • Or Shift + right-click a folder → "Copy as path."
  • For WSL: Windows paths use backslashes (C:\Users\…); WSL needs forward slashes and /mnt/c/. So C:\Users\Pat\work becomes /mnt/c/Users/Pat/work in WSL.

Survival Tips

  • Up arrow recalls your previous command. Keep pressing it to walk back through history.
  • Tab auto-completes file and folder names. Use it constantly — it also prevents typos.
  • Ctrl + C cancels whatever's currently running. If you're stuck, hit it.
  • Ctrl + L (or type clear) clears the screen when it gets noisy.
  • Case matters on Mac/Linux/WSL. Documents and documents are different folders. (Windows native is case-insensitive, confusingly.)
  • The terminal is not scary. You cannot break anything with cd, ls, pwd, or mkdir. Poke around freely.
One command to actually be careful with: rm -rf deletes files and folders permanently — no Trash, no undo. You won't need it for this bootcamp. If an AI ever suggests it, read carefully before running.

Glossary

The words that get thrown around. Skim once, refer back as needed.
CLI
Command-Line Interface. You type commands, the computer runs them. The opposite of a GUI (Graphical User Interface) where you click things.
Terminal
The window you type commands into. On Mac it's called "Terminal." On Windows it's called "Windows Terminal." A terminal is just a container — the actual thing running inside it is a shell.
Shell
The program that interprets what you type. Common ones: bash, zsh (Mac default), PowerShell (Windows default), cmd.exe (old Windows).
Windows Terminal
Microsoft's modern tabbed terminal app. It doesn't do anything by itself — each tab runs a shell (PowerShell, Ubuntu/WSL, Command Prompt, or Git Bash).
PowerShell
Microsoft's modern shell. Built into Windows. Prompt looks like PS C:\Users\you>. Basic navigation works like Mac/Linux; scripting doesn't.
Command Prompt
Windows' old shell (cmd.exe), from the 1980s. Prompt looks like C:\Users\you>. Still works, mostly obsolete. Use PowerShell or WSL instead.
WSL
Windows Subsystem for Linux. Lets you run a real Linux environment on Windows. What we'll use for the bootcamp — Claude Code runs best on Linux/Mac, and WSL gives Windows users the same experience.
Ubuntu
A popular flavor of Linux. When you install WSL, you get Ubuntu by default — the "Ubuntu" app in your Start menu is your WSL shell.
Git Bash / MinGW64
A bash shell bundled with Git for Windows. Title bar often says MINGW64. It's bash-on-Windows via MSYS2. A reasonable fallback if WSL isn't available.
Bash / Zsh
The two shells you'll see in the Linux/Mac world. They're 95% the same for everyday use. Mac's default is zsh; most Linux systems (and WSL's Ubuntu) default to bash.
Prompt
The little bit of text waiting for you to type, usually ending in $ or > or %. It often shows your username and current folder. When tutorials write $ ls, the $ is the prompt — don't type it.
Directory / Folder
Same thing. "Folder" is the GUI word, "directory" is the CLI word. Your hard drive is just nested directories.
Path
The address of a file or folder, like /Users/patrick/Documents/project. Forward slashes on Mac/Linux/WSL, backslashes on native Windows.
Home directory
Your personal folder. On Mac: /Users/yourname. On Linux/WSL: /home/yourname. On Windows: C:\Users\yourname. Shortcut in bash/zsh/PowerShell: ~ (tilde).
Working directory
The folder you're "in" right now — the folder your commands run against. Shown in the prompt, or run pwd to check.

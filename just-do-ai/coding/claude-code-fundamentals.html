Claude Code Fundamentals

This is the core of Week 2: the ten things to know about Claude Code before anything else. Each one is short on purpose. Come back here whenever something on screen surprises you — the answer is probably on this page.

It runs on your computer, for real

Claude Code isn't a chat window that hands you code to paste somewhere. It runs in your terminal, inside your project, and it acts. It uses the tools you already have installed, asks permission to install the ones it needs, and writes ad-hoc code to investigate a problem the way a human operator would.

Ask it to look through a log file for signs of trouble and it reaches for grep, awk, jq and whatever else fits — the same tools a person would use, just faster and without getting bored. It also knows how to install software. It was trained on an enormous amount of Stack Overflow.

A session is a conversation

/context /compact /clear claude --resume

Everything in a session stays in its context: what you said, every file it read, every command it ran. That's what lets it "remember." Context is finite, though, and managing it is a skill we'll spend a whole session on later. For now, three commands:

/context    # what's filling the window right now
/compact    # summarize the conversation so far, keep going
/clear      # start fresh (your CLAUDE.md still loads)

And two ways back into a session you've left:

claude --resume    # pick a previous session from a list
claude -c          # continue the most recent one

Resuming is an essential skill. You will close your laptop mid-task. This is how you pick up where you left off.

It's scoped to your directory

/init /add-dir

Start claude inside your project folder and that folder is its world. It reads and analyzes what's there, and it asks before touching anything outside it. Two good opening moves in a codebase you don't know:

/init    # Claude reads the repo and writes a CLAUDE.md describing it

Or just ask: "What does this code do?" It's a surprisingly good way to meet an unfamiliar repository.

Need a second folder mid-session? /add-dir ../other-project brings it into scope.

The permissions framework

Shift+Tab /permissions

Claude Code asks before it does things, and how often it asks is up to you. Shift+Tab cycles through the modes; the status bar at the bottom shows which one you're in.

Mode
Runs without asking
Use it for
Manual
Reads only. Every edit and every command gets a prompt.
Learning. Unfamiliar code. Anything sensitive.
Accept Edits
File edits and everyday filesystem commands. Shell commands still prompt.
Iterating on code you're reviewing as it goes.
Plan
Reads only. It won't change anything until you approve a plan.
Anything non-trivial. See below.
Auto
Everything. A second model checks each action against what you'd plausibly want and stops for the risky ones.
Long tasks. Where you'll live once you trust it.

Manual used to be the default for everyone; Auto is now the starting mode on Pro, Max and Team plans. Spend your first sessions in Manual anyway — watching what it wants to do is the fastest way to learn what it does.

Plan mode. Use it.

/plan Shift+Tab

For anything non-trivial, start in plan mode. In plan mode Claude Code refuses to change anything. It reads, it thinks, and it keeps asking you questions until it understands what you actually want. Then it writes a plan and asks to leave plan mode so it can execute. Approve the plan, or send it back.

/plan                        # switch into plan mode
/plan fix the login bug      # switch, and start on a task

Why this matters: the time you spend answering its questions up front is the time you'd otherwise spend undoing what it built from a guess.

Interrupt any time

Esc Esc Esc /rewind

Claude Code isn't a black box you have to wait out. Press Esc and it stops mid-turn, keeping whatever it's done so far. Tell it it's going down the wrong rabbit hole, or ask it a question. Then say "continue" or "carry on."

If you need to undo rather than redirect: press Esc twice on an empty prompt, or type /rewind. You get a list of checkpoints, and you can roll back the code, the conversation, or both.

It's fantastic at version control

git /diff

The first time I watched it write a commit message, I thought it was cheating. It signs its name next to yours, and that feels wrong for about a week. Then you notice it writes better commit messages than most people, picks up your team's commit conventions on its own by reading git log, handles branches without drama, and is very good at merging.

Just ask in plain language: "commit this," "put this on a branch," "resolve the merge conflict." /diff shows you everything that's changed in the working tree before you commit.

Pick your model and your effort

/model /effort /usage

/model is the trade-off between the size of the brain and how much you want to spend. In order of capability: Fable, then Opus, then Sonnet, then Haiku. Sonnet is a good everyday balance. Haiku is cheap and fast. Reach for Fable or Opus when the problem is hard. (Fable always thinks before it answers, and needs a plan that includes it.)

/effort is the second dial: how much reasoning it applies to each turn, from low up through xhigh and max. /usage shows where you are against your plan's limits.

Three shortcuts worth learning early

! @ Ctrl+V

! at the start of the prompt runs a shell command directly. The command and its output land in the conversation and Claude responds to them. ! npm test followed by "why did that fail?" is a loop you'll use constantly.

@ followed by a path mentions a file, with autocomplete as you type. It's the cheapest way to point Claude at exactly the thing you mean: "the date parsing in @src/utils/dates.py is off by one."

Ctrl+V pastes an image from your clipboard (Cmd+V in iTerm2, Alt+V on Windows and WSL). Screenshot the broken layout, paste it, say "make it look like this."

CLAUDE.md is for memory

CLAUDE.md /init /memory

Every session starts with a fresh context window. Two things carry over between sessions:

CLAUDE.md is instructions you write. Claude reads it at the start of every session. Put in it what you'd otherwise keep re-explaining: build and test commands, conventions, "always do X" rules. /init writes a first draft by reading your codebase. Keep it under 200 lines — it's context, not enforced configuration, and shorter files are followed more reliably.

Auto memory is notes Claude writes for itself: your preferences, corrections you've given it, things it can't derive from the code. It's on by default. Say "remember that we use pnpm" and it saves a note. Say "add this to CLAUDE.md" and it goes in the shared file instead.

FileScope
./CLAUDE.mdThe project. Commit it — the whole team shares it.
~/.claude/CLAUDE.mdYou, in every project. Personal preferences.
./CLAUDE.local.mdYou, in this project only. Add it to .gitignore.

/memory opens any of these in your editor. /context shows which ones actually loaded into the current session.

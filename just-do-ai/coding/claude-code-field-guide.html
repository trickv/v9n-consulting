01The distinction that matters
An AI agent = an LLM + tools in a loop to achieve a goal.
— Simon Willison
LLM
the engine

Takes text in, predicts text out. Smart, but inert. Describes what to do — can't actually do it.

Claude in your browser. You are the loop.
Agent
an LLM with tools, in a loop

Doesn't just answer — it acts. Works the task step by step, asking before each meaningful action, until it's done or stuck.

Claude Code. It is the loop.
The chat you've been using answers. Claude Code acts — one approved step at a time, until the job is done.
02The working loop

/plan shift+tab

Drop into /plan before real work. Claude reads, thinks, proposes — no file writes. Read the plan. Push back. Refine.

→

Act

Approve the plan and let it execute. Watch the edits stream; interrupt if it veers. Small, bounded tasks beat vague sweeping ones.

→

Commit

Atomic, reviewable commits at every green checkpoint. Your git log is the rollback button when the next loop goes sideways.

03Fundamentals

The primitives

What you'll use in the first ten sessions.
  • /init — reads your codebase, digests what it does, and writes its understanding to CLAUDE.md.
  • @path/to/file — pull any file directly into the turn.
  • # — prefix a line to add it to memory for later turns.
  • /context shows how full the window is; /clear starts fresh; /compact summarizes to keep going.
  • /resume to pick up a prior conversation where you left off.
  • A session's sandbox is the folder you start it in. Nothing above, nothing outside.
  • Default to review-each-edit. Only auto-accept once you trust the task shape.
04Skills

Reusable capability

A folder of instructions Claude loads when the task matches.

A Skill is a directory with a SKILL.md — a named capability Claude pulls in on demand. Think: "how we write tests here," "how we ship a migration," "how we format a PR description," "how Marketing likes our content to look."

  • User-wide: ~/.claude/skills/
  • Project-scoped: .claude/skills/
  • Triggered by the description, not by you naming it.
05Subagents

Specialists on tap

Spawn a focused Claude with its own context window.

Use /agents to create and manage them. A subagent gets a fresh context, a narrowed role, and its results come back summarized — your main session stays clean.

  • Code reviewer that reads the diff without the design-debate baggage.
  • Test-writer that never sees the implementation it's verifying.
  • Researcher that crawls docs and hands you a one-paragraph answer.
06Independent review

Something else checks the work

CodeRabbit. Cubic. Any second pair of eyes that didn't write it.

Open a PR. Let a different reviewer — a different tool, different model, different prompt — evaluate the diff. It catches what the author (you or Claude) was too close to see.

  • CodeRabbit — mature, GitHub-native, inline suggestions.
  • Cubic — newer, same lane, worth a look.

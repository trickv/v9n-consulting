Claude Code → Codex CLI

Already fluent in Claude Code and dropping into OpenAI's Codex CLI? Ten essential slash commands mapped side-by-side, plus a concept table for the bits that don't translate.

Claude Code Codex CLI

Quick Orientation

Same shape, different plumbing. Install, run, point at a project — then everything below is slash commands inside the session.

Claude Code

Install with npm i -g @anthropic-ai/claude-code, launch with claude. Anthropic models (Sonnet, Opus, Haiku). Project memory lives in CLAUDE.md. Config in ~/.claude/.

Codex CLI

Install with npm i -g @openai/codex, launch with codex. OpenAI models (o4-mini default, gpt-4.1, etc). Project instructions in AGENTS.md. Config in ~/.codex/config.toml.

Ten Commands, Side by Side

Roughly in order of how often you'll reach for them.
01 / 10
Initialize a project
Scaffold a file that gives the agent persistent instructions about your repo.
CC/init
CX/init
Claude Code generates a CLAUDE.md with coding conventions, tech stack, and common commands. Codex generates an AGENTS.md scaffold. Same job, different filename. Both also read nested files in subdirectories, which is handy in a monorepo.
02 / 10
Compact the conversation
Summarize earlier turns to free up context window space during long sessions.
CC/compact [instructions]
CX/compact
Both summarize the transcript to free tokens. Claude Code takes optional focus instructions — e.g. /compact focus on the auth refactor — to steer what's preserved. Codex confirms before summarizing.
Habit worth keeping: compact before you hit the wall, not after. Easier to steer the summary when you still have room to review it.
03 / 10
Switch models
Change which model powers the session without restarting.
CC/model
CX/model
Nearly identical. Claude Code picks between Sonnet, Opus, and Haiku. Codex shows a popup with OpenAI models like o4-mini, gpt-4.1, gpt-4.1-mini. Codex also has /fast to toggle a speed-optimized mode for the current model — Claude Code has no direct equivalent, so switch to Haiku for speed instead.
04 / 10
Check usage & cost
See how many tokens you've burned and where your limits stand.
CC/usage + /cost
CX/status
Claude Code splits this in two: /usage for plan limits and rate-limit status, /cost for tokens in the current session. Codex folds everything into /status — active model, approval policy, writable roots, and token usage in one view.
05 / 10
Code review
Ask the agent to review your working tree or recent changes.
CC/review
CX/review
Both review your current changes. Codex pairs naturally with /diff (shows the full git diff including untracked files). Claude Code has no built-in /diff — just ask it to run git diff.
06 / 10
Adjust permissions / approval mode
Control how much the agent can do without asking you first.
CC/permissions
CX/permissions
Same name, different mental model. Claude Code manages tool-level permissions (which tools can run without asking). Codex uses approval presets: Auto (fully autonomous), Suggest (propose, then confirm), Read Only (no file writes). You can also set approval mode at launch with codex --approval-mode auto.
Sandbox note: Claude Code's /sandbox enables filesystem and network isolation. Codex sandboxes commands by default and uses /sandbox-add-read-dir to grant extra read access.
07 / 10
MCP servers & external tools
Manage Model Context Protocol integrations.
CC/mcp
CX/mcp
Both list configured MCP tools. Claude Code uses /mcp to manage connections and handle OAuth interactively. Codex uses /mcp to list tools, but servers are configured in ~/.codex/config.toml rather than via the CLI. Codex also has /apps to browse and attach connector-style integrations.
08 / 10
Edit memory & configuration
Update persistent project instructions or personal preferences.
CC/memory + /config
CX/personality + config.toml
Claude Code has /memory to edit CLAUDE.md in-session and /config for the settings UI. Codex doesn't have an in-session memory editor — you open AGENTS.md in your editor. For tone, Codex has /personality (friendly, pragmatic, or none). Persistent config lives in ~/.codex/config.toml.
09 / 10
Reset the session
Start fresh without leaving the terminal.
CC/clear
CX/clear or /new
Claude Code's /clear wipes the conversation and resets context. Codex offers two: /clear clears the terminal and starts a fresh chat, /new starts a new conversation but keeps the terminal view. Codex also has /fork to branch into a parallel thread and /resume to reload a previous session.
Session resume: Codex's /resume is roughly equivalent to Claude Code's claude -c (continue last) or claude -r (resume specific session) CLI flags.
10 / 10
Plan before executing
Ask the agent to propose a plan before writing code.
CCask Claude to plan
CX/plan
Codex has a dedicated /plan command that switches into plan mode — the agent proposes an execution plan before any implementation. You can pass an inline prompt: /plan migrate this service to TypeScript. Claude Code has no built-in equivalent, but you can prompt with "plan this first, don't implement yet" or wrap it in a custom skill.

Key Concept Mapping

The bits that aren't a single slash command — where the tools diverge at the configuration and file-layout level.
Concept Claude Code Codex CLI
Project instructions file CLAUDE.md AGENTS.md
Config location ~/.claude/settings.json ~/.codex/config.toml
Custom commands .claude/skills/ or .claude/commands/ Custom slash commands (community-built)
Subagents .claude/agents/ with YAML frontmatter /agent to switch threads
Default model Claude Sonnet o4-mini
Continue last session claude -c /resume
Non-interactive / scripting claude -p "prompt" codex "prompt" (prompt as arg)
Approval / autonomy levels Per-tool allow/deny Presets: Auto, Suggest, Read Only
Git diff viewer Ask: "show me the diff" /diff (built-in)
Copy last response Select + copy manually /copy (built-in)

The Mental Shifts

If you remember nothing else, remember these.
  • Nearly 1:1: /init, /compact, /model, /review, /permissions, /mcp. The mental model transfers cleanly.
  • Where Codex has more: /plan (dedicated plan mode), /diff (built-in git diff), /copy (clipboard), /fork (branch conversations), /fast (speed toggle). Things you'd do manually or via custom skills in Claude Code.
  • Where Claude Code has more: /memory for in-session CLAUDE.md edits, /cost + /usage as separate detailed views, /sandbox for isolation, and a more mature skills/subagents system.
  • The biggest shift: AGENTS.md instead of CLAUDE.md, TOML config instead of JSON, and permissions as preset tiers (Auto / Suggest / Read Only) rather than per-tool granularity.

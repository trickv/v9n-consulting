Claude Code Fundamentals: The First 15 Commands

The handful of commands and concepts you need to get real work done your first week with Claude Code. Nothing fancy — just the muscle memory that makes the rest click.

Six Things to Internalize First

Claude Code isn't ChatGPT in a terminal. These concepts shape everything below.
01 · Real execution, real files

Claude Code runs on your computer. It uses the tools you already have — grep, awk, jq, git — and asks permission to install more if it needs them. When you say "look at this log file," it investigates the way a human operator would, just faster. It's trained on Stack Overflow; it knows how to install software.

02 · A session is a conversation

Everything you've said this session is in context — Claude remembers it. That's a feature (build on previous turns) and a trap (context fills up, gets stale, or wanders off topic). Knowing when to start fresh vs. resume is a real skill.

03 · Scoped to your directory

Claude Code works inside the folder where you launched it. It will read files outside that directory, but it asks permission first. Inside, it reads and analyzes freely. A great first prompt in a new repo: "What does this code do?"

04 · Permissions matter

It's built for safety. It asks before editing files, running processes, installing things, or touching anything outside your directory. It makes mistakes sometimes — the permission prompt is your safety net. If you ever run in YOLO mode, run it in a sandbox.

05 · Interrupt any time

Hit Esc. That stops whatever it's doing. Tell it it's going down the wrong rabbit hole, or ask a clarifying question. Then say "continue" or "carry on" to pick back up. You're the driver, not a passenger.

06 · Excellent at version control

The first time you see Claude write a git commit message, it feels like cheating — it signs its name next to yours. It feels wrong for about a week. Then you realize the commit messages are better than what you'd write, and you stop fighting it.

Installing & Starting

One-time setup, then two commands to run it.
$ npm install -g @anthropic-ai/claude-code   # one-time install
$ cd ~/my-project                             # go to your repo
$ claude                                      # start a session

That's it. You're now talking to Claude, scoped to this directory. Ask it anything.

The Commands

Slash commands run inside a Claude session. CLI flags go on the claude command itself when you launch.
01 /init "teach Claude about this repo"

Run this the first time you open a project. Claude scans the codebase and writes a CLAUDE.md file at the root — coding conventions, tech stack, common commands, important files. Every future session reads it automatically.

Check it into git. Edit it by hand when things change. Treat it like a README for your AI collaborator.

02 Esc "stop, I want to say something"

Not a slash command — a single key. Press Esc any time Claude is running to interrupt it. You can correct course, ask a question, or kill a bad idea before it writes ten files.

Habit worth building: interrupt the moment you spot it going sideways. Cheaper than letting it finish and undoing the damage.
03 /model "pick Opus, Sonnet, or Haiku"

Switch models without restarting. Rough guide:

  • Opus — smartest. Use for planning, hard debugging, ambiguous problems.
  • Sonnet — the daily driver. Strong and balanced.
  • Haiku — fast and cheap. Great for routine edits, repetitive tasks, or when you're iterating a lot.

Starting with Sonnet is almost always the right call. Reach for Opus when stuck.

04 claude --resume "pick up where I left off"

Launch this way instead of plain claude to reload a previous session. Claude lists recent sessions; you pick one. The full conversation history is back — no re-explaining.

Shortcut: claude -c continues your most recent session without the picker.

Essential skill: knowing when to resume vs. start fresh. Resume when the context is still relevant. Start fresh when switching tasks — stale context makes Claude worse, not better.
05 /clear "start the conversation over"

Wipes the current conversation and starts fresh — same directory, same CLAUDE.md, but no prior turns. Use this when you're switching to a new task or the session has gone off the rails.

06 /compact "summarize so we can keep going"

Summarizes earlier turns to free up context window space. Use it before you hit the wall on a long session. Optional: pass focus instructions — /compact focus on the auth refactor — to steer what gets preserved.

07 /permissions "what can Claude do without asking?"

Review and adjust which tools run without prompting. Over time you'll trust Claude with things like git status or npm test and add them to the allow list. Destructive stuff stays behind a prompt.

Don't blanket-allow everything on day one. The prompts feel annoying for about a week, then you learn which categories are safe to allow and which aren't. Let that calibration happen.
08 "commit this" "let Claude write your git commit"

Not a slash command — just ask. Claude reads the diff, writes a good commit message, and commits. It co-signs with you (look for Co-Authored-By: Claude). Feels wrong at first. Then you read the message and realize it's better than yours.

Works for branches, PRs, rebases, merge conflicts, the whole pipeline. If git confuses you, Claude is a patient guide.

09 "what does this code do?" "the best first prompt in any repo"

Point Claude at an unfamiliar codebase and ask. It reads the files, traces entry points, and explains the architecture in plain language. Faster than reading the README. Often more accurate than the README.

10 /cost "how many tokens have I burned?"

Shows token usage for the current session. Pair with /usage to see your plan limits. Useful when a session feels slow — often it's because context is full, and /compact or /clear is the fix.

11 /help "show me everything I'm forgetting"

Lists every slash command with a short description. When you know the command exists but forgot the name.

12 /memory "edit CLAUDE.md in place"

Opens CLAUDE.md for editing without leaving the session. Useful when you realize mid-session that a rule — "never touch the migrations folder," "always use pnpm not npm" — should be permanent.

13 /review "critique my working tree"

Asks Claude to review the code you've changed. Catches small bugs, missed edge cases, and "did you really mean to do this?" moments before you commit. Not a replacement for a human reviewer — a complement.

14 claude -p "prompt" "one-shot, no chat window"

Run Claude non-interactively — give it a prompt, get the answer, exit. Perfect for scripting, pre-commit hooks, or piping a question through from another tool.

$ claude -p "summarize the last 10 commits"
15 "plan first, don't implement yet" "think before you code"

Not a slash command — a prompt pattern. For anything non-trivial, ask Claude to propose a plan before writing code. Read it, push back, adjust. Then say "go ahead." Saves far more time than it costs, especially on anything that touches more than one file.

Safety Notes

It will make mistakes. Sometimes small, occasionally expensive. The permission prompts exist for a reason — read them before clicking yes. Review diffs before committing. Run tests.
YOLO mode (--dangerously-skip-permissions) belongs in a sandbox. Running Claude without permission prompts on your real machine is how you end up with deleted files, broken shells, or surprise rm -rf. If you want autonomy, get it via a container, VM, or isolated directory — not by disabling the safety net.
